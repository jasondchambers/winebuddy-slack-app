winebuddy-slack-app

WineBuddy Architecture

A Slack bot that answers questions about the wine cellar. It calls the Claude API, which looks bottles up through the winebuddy CLI. Each Slack thread is one conversation.

What happens when someone asks a question

  1. 1
    Slack delivers the message

    Over Socket Mode, a connection the bot opens, so the server needs no public endpoint. main.py posts “WineBuddy is working on it...” in the message's thread. For a reply in a thread, it reads the last 20 thread messages with conversations.replies.

  2. 2
    main.py hands the question to ask.py

    Along with the thread so far as earlier messages, so Claude can answer follow-ups like “which of those is ready?”

  3. 3
    The cellar is refreshed

    winebuddy --refresh brings the cellar up to date. Claude gets the refresh output so it can mention new or finished bottles.

  4. 4
    Claude reads the question

    Sonnet 5.5, with the winebuddy skill (SKILL.md) and the bot's Slack formatting rules as its system prompt, and two tools it can call.

  5. 5
    Claude looks bottles up

    Each query_wines or discover call runs the winebuddy CLI and returns JSON. Steps 4 and 5 repeat until Claude answers, up to 10 rounds.

  6. 6
    The answer streams into the thread

    The “working on it” message is updated every 2 seconds as text arrives, then once more with the full answer.

Conversations

A new message in the channel or a DM starts a conversation. Replies in its thread continue it. Nothing is stored: the history is read back from Slack each time, capped at 20 messages.

Guardrails

  • Claude has no shell. Its tools run the winebuddy CLI with fixed arguments.
  • One question makes at most 10 rounds of tool calls.
  • 5 seconds between requests per person, 2,000 characters per message.
  • Messages from bots are ignored, so it never replies to itself.

Deploys

deploy.sh copies the code to the container, pulls the winebuddy repo into ~/.winebuddy, runs uv sync and restarts the service. Secrets come from deployment.env, generated from 1Password. The cellar data is kept up to date separately by winebuddy-sync-with-cellartracker.
